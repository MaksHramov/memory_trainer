# Memory Trainer — тренажёр памяти и внимания

Веб-приложение с двумя короткими упражнениями, личной историей результатов и отдельной страницей администратора. Пользователь работает в браузере через React-интерфейс; сервер на Spring Boot сохраняет учётные записи и результаты в PostgreSQL.

Проект является учебным прототипом и не предназначен для медицинской диагностики.

---

## 1. Общая характеристика

### Режим пользователя

- регистрация и вход;
- упражнение «Память»: запоминание пяти слов за 25 секунд и выбор запомнившихся слов;
- упражнение «Внимание»: пять заданий на поиск отличающейся фигуры в сетке 3 × 3;
- просмотр истории собственных результатов.

### Режим администратора

На отдельной странице `/admin` администратор может просматривать, создавать, изменять и удалять пользователей, а также просматривать и редактировать их результаты. Доступ проверяется на сервере по роли `ADMIN`.

---

## 2. Функциональные требования

### ФТ-1 — Учётные записи

При регистрации пользователь задаёт логин и пароль. Повторяющийся логин не допускается; пароль хранится в виде хеша. После входа сервер выдаёт JWT-токен, который клиент передаёт с защищёнными запросами.

### ФТ-2 — Тренировка памяти

Приложение показывает пять случайных слов на 25 секунд. Затем пользователь выбирает их из списка с дополнительными словами. Клиент подсчитывает количество правильно выбранных слов и отправляет результат на сервер.

### ФТ-3 — Тренировка внимания

Пользователь проходит пять раундов. В каждом раунде одна фигура в сетке 3 × 3 отличается от остальных. После последнего ответа клиент подсчитывает баллы и отправляет результат на сервер.

### ФТ-4 — История результатов

Для каждой попытки сохраняются пользователь, тип упражнения, набранный и максимальный балл, время выполнения. Обычный пользователь видит только собственную историю.

### ФТ-5 — Администрирование

Администратор управляет учётными записями и результатами через защищённые REST-запросы. Обычному пользователю эти операции недоступны.

## 3. Архитектура системы

Проект разделён на клиентскую и серверную части:

```text
React (View) → REST-контроллеры (Controller) → сервисы → репозитории → PostgreSQL
                                                  ↓
                                          User и TestResult (Model)
```

- `frontend/src/pages` — страницы упражнений, результатов, входа и админки;
- `frontend/src/api` — HTTP-запросы к серверу;
- `backend/.../controller` — REST-маршруты;
- `backend/.../service` — логика регистрации, авторизации, результатов и администрирования;
- `backend/.../models` — модели `User` и `TestResult`;
- `backend/.../repository` — доступ к PostgreSQL через Spring Data JPA;
- `backend/.../dto` — форматы запросов и ответов API;
- `backend/.../config`, `security`, `exception` — настройки, проверка доступа и обработка ошибок.

## 4. Модель данных

| Модель | Назначение | Основные поля |
|---|---|---|
| `User` | Учётная запись | `id`, `username`, `password`, `role`, `createdAt` |
| `TestResult` | Одна попытка упражнения | `id`, `user`, `testType`, `score`, `maxScore`, `completedAt` |

В PostgreSQL им соответствуют таблицы `users` и `test_results`. Один пользователь может иметь много результатов; каждый результат принадлежит одному пользователю.

Типы упражнений: `MEMORY_WORDS` и `ATTENTION_ODD_ONE`. Роли: `USER` и `ADMIN`.

## 6. Быстрый запуск через Docker

Понадобится Docker с поддержкой Compose. Из корня проекта выполните:

```bash
docker compose up --build -d
```

После запуска доступны:

| Адрес | Назначение |
|---|---|
| http://localhost:3001 | Приложение |
| http://localhost:3001/admin | Вход в админку |
| http://localhost:8080/docs | Документация API |
| http://localhost:8080/api/health | Проверка доступности сервера |

Остановить контейнеры можно командой `docker compose down`. Данные PostgreSQL хранятся в Docker-томе `postgres_data` и при обычной остановке не удаляются.

Для публичного развёртывания необходимо заменить пароли базы данных, пароль начального администратора и секрет JWT, заданные в конфигурации проекта. Не публикуйте реальные пароли в репозитории.

### Локальный запуск для разработки

Нужны Java 21, Maven, Node.js и доступная PostgreSQL с параметрами из `backend/src/main/resources/application.yml` (по умолчанию `localhost:5432`). Затем в двух терминалах:

```bash
cd backend
mvn spring-boot:run
```

```bash
cd frontend
npm install
npm run dev
```

Vite выводит адрес клиентского приложения в терминале; обычно это http://localhost:5173. Если API запущен не на `localhost:8080`, задайте `VITE_API_URL` для фронтенда.

## 7. REST API

| Метод | Маршрут | Действие |
|---|---|---|
| `POST` | `/api/auth/register` | Регистрация |
| `POST` | `/api/auth/login` | Вход и получение JWT |
| `POST` | `/api/tests/results` | Сохранение своего результата |
| `GET` | `/api/tests/results` | Получение своей истории |
| `GET`, `POST` | `/api/admin/users` | Список и создание пользователей |
| `PUT`, `DELETE` | `/api/admin/users/{id}` | Изменение и удаление пользователя |
| `GET`, `POST` | `/api/admin/users/{id}/results` | Результаты пользователя и создание результата |
| `PUT`, `DELETE` | `/api/admin/users/{id}/results/{resultId}` | Изменение и удаление результата |
| `GET` | `/api/health` | Проверка сервера |

Защищённые запросы требуют заголовок `Authorization: Bearer <token>`. Полные схемы запросов и ответов доступны в Swagger по адресу `/docs`.

## 8. Проверка качества

Модульные тесты проверяют `AuthService`, `TestResultService` и `AdminService`. Для их запуска PostgreSQL и Docker не нужны:

```bash
cd backend
mvn test
```

Запускайте тесты на Java 21: более новая версия JDK может быть несовместима с используемой версией Mockito/Byte Buddy. Сборка клиентской части проверяется командой:

```bash
cd frontend
npm run build
```

---

## 9. Основной сценарий работы

1. Пользователь регистрируется и входит в систему.
2. Выбирает упражнение «Память» или «Внимание».
3. Выполняет задание и получает баллы.
4. React отправляет результат на сервер через REST API.
5. Сервер связывает результат с учётной записью и сохраняет его в PostgreSQL.
6. Пользователь просматривает историю в разделе «Результаты».
